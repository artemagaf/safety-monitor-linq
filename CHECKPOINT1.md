# Чек-поинт 1 — как мы видим решение

Шпаргалка к созвону. На 1-м чек-поинте нужно рассказать экспертам и трекерам, **как команда видит решение**.
Говорить 3–5 минут, остальное — вопросы.

---

## 1. Одной фразой (≈15 сек)

> Десктопное приложение, которое смотрит видео с камер цеха, с помощью нейросетей на ускорителе LinQ
> находит опасное поведение и нарушения СИЗ, и сразу присылает мастеру **одно** оповещение
> с 5-секундным клипом, камерой, участком, временем и типом нарушения.

## 2. Какую проблему решаем (≈30 сек)

- Камеры есть почти везде, но используются как архив — нарушения находят **после** травмы.
- Оператор не может следить за десятками экранов: внимание падает через 20–30 минут.
- Нет статистики: где, когда и какие нарушения повторяются.
- Главный критерий из кейса — **быстро и надёжно** сообщить о реальном инциденте, без потока ложных тревог.

## 3. Что умеет система (≈1 мин)

**Поведение во времени** (задача №1 кейса) — приоритет:

| Сценарий | Как распознаём |
|---|---|
| Падение и неподвижность на полу — критичный инцидент | нейросеть позы человека (17 точек скелета) + «лежит дольше N секунд» |
| Бег по цеху | скорость перемещения человека между кадрами относительно его роста |
| Телефон при работе у станка | детекция телефона в руке у человека в зоне станка |
| Опасное сближение с техникой и транспортом | детекция техники + расстояние до человека |
| Курение | детекция сигареты у человека |

**СИЗ станочников** — наша дополнительная фишка:
- нет защитных очков у токарного станка;
- **перчатки у вращающихся частей** (токарный, сверлильный): одно и то же СИЗ на одном станке обязательно, на другом запрещено, и правило задаётся для каждого станка.

## 4. Как это работает — архитектура (≈1 мин)

```
Камеры (RTSP) / видео / набор картинок
      │
      ▼
 Нейросеть на LinQ  ──►  трекинг людей  ──►  правила по зонам  ──►  сглаживание
 (детекция + поза)       (ID человека)       (станок, опасная     (нарушение ≥ 1.5 с,
                                              зона, СИЗ)            не случайный кадр)
      │
      ▼
 Запись кусками по 5 секунд: чистый кусок удаляется, с нарушением — сохраняется клип
      │
      ▼
 Десктопное приложение: лента событий, кадр и клип, журнал с фильтрами, статистика
```

Ключевые решения:
- **Одно нарушение = одно оповещение.** Пока человек в кадре, дублей нет (требование кейса).
- **Ложные срабатывания гасим во времени:** событие, только если нарушение держится несколько секунд подряд.
- **Настройка камеры без кода:** зоны, станки и правила — в конфиге для каждой камеры.
- **Память не забивается:** хранится только видео с нарушениями, лимит на объём.
- **Расширяемость:** новый тип нарушения — это новый класс модели и правило, конвейер не меняется.

## 5. Технологии — что используем (≈1 мин)

| Слой | Что | Зачем |
|---|---|---|
| Нейросети | **YOLO11** (Ultralytics) — детекция; **YOLO11-pose** — поза человека | быстрые, точные, легко дообучаются и экспортируются |
| Данные | **SH17** — 8 тыс. фото с производств (очки, перчатки, руки, каски); COCO — люди, телефоны, транспорт | готовые разметки под наши классы |
| Без обучения | **YOLO-World** — поиск объектов по текстовому описанию (CLIP) | быстрый старт и авторазметка своих кадров |
| Ускоритель | **LinQ TPU**: ONNX → SDK LinQ (квантование INT8, компиляция) → программа `.tpu` → инференс через Python API | требование кейса, отечественная платформа |
| Видео и логика | Python, OpenCV, свой трекер, SQLite | обработка потоков, журнал событий |
| Приложение | **десктоп на Python (PySide6 / Qt)** | локальный GUI разрешён кейсом; работает без интернета, на площадке |
| Уведомления | в приложении + Telegram / webhook | мастер получает тревогу сразу |

## 6. Как работаем с LinQ (≈40 сек)

1. Обучаем модель → экспорт в **ONNX** с фиксированным размером входа.
2. **SDK LinQ** квантует (INT8, калибровка на 200 кадрах из наших данных) и компилирует в программу `.tpu`.
3. На ускорителе выполняется **только сама нейросеть**; подготовка кадра и разбор результата — наш код на CPU.
4. Корректность доказываем **сверкой с эталоном** (та же модель на CPU): совпадение детекций > 95%.
5. Скорость доказываем **замерами**: мс на кадр, FPS, p95 — отсюда сколько камер тянет один ускоритель.
6. Если ускоритель недоступен — система автоматически продолжает работать на CPU.

## 10. Если спросят «почему так»

- **Почему YOLO?** Стандарт для детекции в реальном времени; хорошо квантуется в INT8 и экспортируется в ONNX — то, что нужно для LinQ.
- **Почему не одна большая модель?** Детекция объектов и поза человека — разные задачи; две маленькие модели быстрее и точнее одной универсальной.
- **Почему десктоп?** Предприятиям часто нельзя выпускать видео с камер в интернет; приложение работает внутри контура рядом с ускорителем.
- **Как боретесь с ложными тревогами?** Сглаживание во времени, привязка СИЗ к конкретному человеку, отдельные классы «без каски» / «без перчатки» — модель ищет доказательство нарушения, а не отсутствие объекта.
- **Как масштабировать?** Один ускоритель обслуживает несколько камер по очереди; по замерам FPS считаем, сколько камер на один LinQ.
